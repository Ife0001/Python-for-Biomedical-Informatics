# Biomedical Text Mining and Clinical Phrase Screening

**Python · Regular Expressions · Tokenization · Document Frequency · Reproducible Text Processing**

## Project question

How can simple, explainable Python text-processing techniques help profile terms across a collection of biomedical documents and identify passages containing follow-up expressions for later human review?

## Source and provenance

Adapted as an independent portfolio project from BMI 5007 text-processing exercises: (1) token counts across a provided MEDLINE abstract corpus; (2) searching text notes for terms such as `diabetes` and phrases such as `follow-up`, `follow up`, `followup`, and `f/u`. The original coursework code and instructor templates are **not included**.

The **five fictional examples generated by `src/generate_demo.py`** are used for the public demonstration. No patient records or verbatim MEDLINE abstract files are distributed. For a local analysis of the supplied `medline.zip`, extract its `medline` folder under `data/` and point the program at it.

## Pipeline

1. Discover `.txt` files in an input folder; exclude metadata file `readme.md.txt`.
2. Normalize case and tokenize words for lexical counting.
3. Compute document token totals, distinct-term counts, selected-term frequency, and corpus-wide term frequency.
4. Flag documents containing follow-up *phrases* using a transparent regular expression.
5. Export corpus-level metrics and common terms to JSON/CSV. Per-document metrics are available for fictional demo inputs.

## Run locally

Requires Python 3.10+ and no third-party packages.

From the `03-biomedical-text-mining` directory:

```cmd
python -m unittest discover -s tests -v
python src/generate_demo.py
python src/analyze.py
```

Outputs (demo only): `outputs/corpus_summary.json`, `outputs/top_terms.csv`, and `outputs/document_summary.csv`.

To analyze the original MEDLINE extracts **locally without writing document identifiers**:

```cmd
python src/analyze.py --input data/medline --output outputs/medline_private --private
```

For note text kept locally:

```cmd
python src/analyze.py --input data/notes --output outputs/notes_private --private
```

The `--private` option suppresses per-document outputs, **but does not guarantee privacy**: aggregate terms and rare words can still disclose sensitive content. Do not share those output files without review. Neither source text nor analytical outputs are committed by default.

## Methods and interpretation

- This is **lexical screening, not clinical concept extraction**. It does not recognize coding ontologies, negation, temporality, abbreviations beyond specified patterns, or patient context. A mention of diabetes in “no diabetes” still counts.
- A follow-up phrase is **not** evidence that a follow-up appointment occurred, was required, or was completed. Flagged text requires manual verification.
- Token frequency depends on punctuation and tokenization choices. No stemming, lemmatization, or stop-word filtering is applied.
- These measures are not patient prevalence, diagnosis counts, or patient safety outcomes.
